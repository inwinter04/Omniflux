# 多租户与组织模型

在企业级 AI 架构中，安全隔离、分级授权与成本责任归属是系统治理的核心诉求。Omniflux 设计了一套层级严谨的多租户模型。

## 层级架构设计

Omniflux 采用 **组织 → 部门 → 项目 → 应用 → API Key** 的树状层级关系，并配合基于角色的用户管理（RBAC）：

![Omniflux 多租户组织模型](/assets/org-model.zh-CN.png)

### 各层级职责与边界

| 层级对象 | 治理作用 | 边界与特性 |
| :--- | :--- | :--- |
| **组织 (Organization)** | 顶级租户边界 | **数据绝对隔离**。组织之间的模型服务、用户、API Key、计费与审计互不可见；可作为企业总线或独立子公司划分。 |
| **部门 (Department)** | 行政或业务分组 | 组织内部的管理归属单元；支持按部门汇总成本报表并进行大范围的资产权限下发。 |
| **项目 (Project)** | 核心业务与控制单元 | **预算与资产授权的基本单元**。模型服务、提示词模板、智能体的调用权限均绑定到项目；项目具备独立的月度/季度成本预算。 |
| **应用 (Application)** | 具体客户端/系统载体 | 项目内部的具体微服务或系统实体（如“智能客服机器人”、“研发辅助助手”），用于更细维度的用量归集。 |
| **API Key** | 数据面认证与鉴权凭证 | 明文仅在创建时展示一次，数据库存储加盐哈希（Pepper）。每个 Key 可配置独立的每分钟限流阈值（Rate Limit）。 |
| **用户与角色** | 控制台成员操作权限 | 负责管理台的日常运维、审批与观测，按角色严格约束管理接口权限。 |

## 角色权限划分 (RBAC)

Omniflux 内置四级清晰的管理台用户角色：

1. **平台管理员 (Platform Admin)**：
   - 拥有全局最高权限。
   - 负责全局系统设置（如开放自主注册、配置全平台 SMTP 邮件服务器）。
   - 管理全平台的组织、全量用户启停与密码重置。
2. **组织所有者 (Organization Owner)**：
   - 管理当前组织的全部事务。
   - 能够创建与分配部门、项目，接入组织级 Provider 账号，管理组织内成员与权限分配。
3. **开发者 (Developer)**：
   - 在已授权的项目范围内创建模型服务、维护 PromptTemplate 模板、调试与发布 Agent。
   - 签发属于本项目的 API Key 并查看所属项目的调用日志与用量统计。
4. **查看者 (Viewer)**：
   - 只读权限。可查看已授权项目的监控大盘、调用统计与审计日志，无权修改配置或签发密钥。

## 资产授权与作用域机制

在 Omniflux 中，模型服务（Model Service）、提示词模板（PromptTemplate）以及智能体（Agent）统称为**受治理资产**。

资产通过明确的权限级别授予业务项目：
- `read` 权限：允许查看资产的元数据、结构定义与列表（例如 `GET /v1/models` 中仅展示具有 read 权限的模型服务）。
- `invoke` 权限：允许实际发起数据面执行（如请求 `/v1/chat/completions`、渲染 Prompt 或执行 Agent 对话）。

如果业务调用方尝试请求未被授权或仅有 `read` 权限的资产，数据面网关将直接返回 HTTP 403 `model_access_denied` 错误，请求**绝不会进入上游大模型**，亦不会产生任何计费。

## 启停级联控制与安全防线

为了应对突发安全事件或欠费风险，Omniflux 支持多维度的瞬时阻断能力：
- **项目级停用**：停用项目后，该项目下属的所有 API Key 立即失效，返回 `project_disabled`。
- **应用级停用**：精确暂停某一个业务调用端，返回 `application_disabled`。
- **Key 级停用**：当某个 API Key 疑似泄露时，管理台可一键停用该 Key，返回 `api_key_disabled`。

停用指令由内存与 Redis 状态联动保障，**毫秒级生效**，阻断的请求均不会向上游转发。
