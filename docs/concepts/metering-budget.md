# 计量计费、预算与限流

对企业来说，AI 基础设施不仅要“跑得通”，更要“算得清、控得住”。Omniflux 内置了精细化计量归因、多币种成本对账与高性能防穿透预算限流机制。

## 细粒度计量归因模型

每次数据面请求完成（无论是成功还是部分失败），系统都会生成一条不可篡改的 `usage_records` 计量记录。

Omniflux 支持从五个核心维度进行多角度归因交叉分析：
1. **组织 (Organization)**：核算法人主体或事业部的综合成本。
2. **部门 (Department)**：输出月度行政成本账单。
3. **项目 (Project)**：监控研发业务线的立项专项预算。
4. **应用 (Application)**：精准归因具体微服务或机器人的用量峰谷。
5. **API Key / Provider / 模型**：评估单 Key 消耗水平以及各供应商的成本效益。

每条计量记录完整记录：
- `prompt_tokens`（输入 Token 数量）
- `completion_tokens`（输出 Token 数量）
- `total_tokens`（总 Token 数量）
- `cost` 与 `currency`（根据计费模型计算的实际成本金额与币种）
- `latency_ms`（请求总耗时）及 `first_token_ms`（流式首包耗时）

## 多币种与套餐混合结算

企业接入的模型厂商常涉及不同货币体系（如国内厂商使用 CNY，海外厂商使用 USD）。

- **多币种独立账单**：系统支持在模型服务级别声明计费币种，账单统计时不强制暴力折算，保持各币种账目原汁原味。
- **套餐模式（Coding / Token Plan）支持**：针对包含周期包月、按月重置额度的特定套餐，管理台支持展示套餐已用量与剩余用量，清晰区分“按量计费余额”与“周期包额度”。

## 预算熔断风控 (Budget Control)

Omniflux 在项目级别提供严格的预算上限配置（如“本月预算上限 ¥5000”）。

### 预算核算机制（后付口径）
- **请求前预检**：每次请求进入网关前，系统会校验当前项目已结算的历史累计金额是否已触碰预算警戒线。若已超限，直接阻断并返回 `budget_exceeded` 错误，阻止上游调用。
- **请求后结算**：上游响应成功并解析出准确 Token 消耗后，原子累加计费。
- **并发在途说明**：并发极高且同时到达的大批在途请求，可能在毫秒级微量越过限额（这与业界主流网关保持一致），随后系统将迅速阻断后续全部请求。

## 分布式窗口限流 (Rate Limiting)

为了保护上游厂商配额以及防止客户端异常循环调用，Omniflux 基于 Redis 构建了多层限频防护：

1. **全局默认限流 (`OMNIFLUX_RATE_LIMIT_PER_MIN`)**：系统默认兜底阈值（默认 60 次/分钟）。
2. **API Key 自定义限流 (`rate_limit_per_min`)**：在为核心系统或批处理任务签发 API Key 时，可针对单个 Key 设置独立的频控速率。
3. **限频阻断行为**：当某个 Key 在 1 分钟固定窗口内请求数超标，网关直接返回标准 HTTP 429 `rate_limit_error`，请求**不进入上游模型，亦不计入 Token 消耗**。

## 异常对账与运维任务 (Reconciliation)

在极端生产场景下（如上游模型生成到一半发生网络中断、Omniflux 服务实例突发异常重启等），可能存在处于 `pending` 状态的在途请求。

Omniflux 内部运行定时对账任务：
- 扫描超时的悬挂事务；
- 依据已有数据包完成状态补齐或安全判定为失败定稿；
- 保证账目的一致性与准确性，杜绝“幽灵扣费”与账目不平。
