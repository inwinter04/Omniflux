# 环境要求与架构规划

在生产环境中部署 Omniflux 之前，请参考本篇建议规划服务器算力、数据库规格与网络拓扑。

## 软件依赖版本要求

| 软件组件 | 最低版本要求 | 推荐版本 | 作用说明 |
| :--- | :--- | :--- | :--- |
| **Go 运行时** | 1.27+ | 最新稳定版 | 服务端编译与源码运行环境。 |
| **Node.js** | 20+ | 22 LTS | 仅在独立二次开发或构建 Vue3 管理台前端时需要。 |
| **pnpm** | 10.5+ (推荐 Corepack) | 12.18+ | 前端依赖管理工具。 |
| **PostgreSQL** | 16+ | 17 (Alpine / Cloud RDS) | 核心业务数据库，存储多租户元数据、凭证与计量日志。 |
| **Redis** | 7.0+ | 8.0+ | 高性能分布式频控与限流存储。 |
| **Docker** | 20.10+ | 最新 Docker CE | 推荐的容器化部署底座。 |

## 服务器规格选型指南

Omniflux 核心数据面采用纯 Go 语言编写，内存占用极低且并发吞吐极佳。资源瓶颈通常取决于下游并发请求量及是否持久化海量审计日志。

| 业务规模 | 典型 RPS (请求/秒) | 建议节点配置 | PostgreSQL 配置建议 | Redis 配置建议 |
| :--- | :--- | :--- | :--- | :--- |
| **轻量级 / 测试** | < 20 RPS | 1 核 CPU, 2 GB 内存 | 1 核 2GB, 20GB SSD | 512 MB 内存 |
| **中型企业生产** | 20 ~ 200 RPS | 2 节点 (每节点 2 核 4GB) | 2 核 4GB, 100GB SSD | 2 GB 内存 |
| **大型高并发企业** | 200 ~ 2000+ RPS | 3+ 节点水平扩展 (4 核 8GB) | 4 核 16GB+, 专用只读从库 | 4 GB 内存, 高可用主从架构 |

## 推荐生产拓扑结构

在企业正式落地环境中，强烈建议将 Omniflux 部署在私有网络（VPC）中，并通过反向代理对外暴露服务：

![Omniflux 推荐生产拓扑结构](/assets/production-topology.zh-CN.png)

- **反向代理层**：负责终结 HTTPS/TLS 证书、配置 HTTP/2 支持，并对长链接 Server-Sent Events (SSE) 开启流式直通（禁用 `proxy_buffering`）；
- **数据面与管理台统一**：Omniflux 单个二进制文件同时承载 `/v1/*` 数据面和 `/admin/` 管理台，简化多实例水平扩缩容；
- **凭据静态加密**：所有写入数据库的上游 Key 均由应用层 AES-256-GCM 加密，即使数据库备份泄露亦不会导致真实 Provider 密钥外溢。
