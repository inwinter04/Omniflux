# Omniflux 是什么

Omniflux 是一个面向企业的 **AI 服务控制平面（AI Service Control Plane）**。

在企业智能化转型的过程中，团队往往会采购或自建多种大语言模型（如 DeepSeek、OpenAI、智谱 GLM、阿里通义千问、Kimi 以及内部私有部署的 vLLM / Ollama）。然而，分散的接入方式很快会带来多重治理难题：

- **代码耦合严重**：业务系统直接硬编码特定厂商的模型标识与 API Key，切换模型或服务商需要修改并发布业务代码；
- **成本与用量黑盒**：各业务线与团队各自持有 Key，缺少统一的细粒度用量归因、预算控制与对账体系；
- **缺乏可用性与容灾机制**：单一供应商遇到限频、网络抖动或服务故障时，业务请求直接失败，无法无感故障转移；
- **权限与数据风控缺失**：缺乏统一的访问控制、多租户数据隔离，难以审计谁在何时调用了哪个模型以及耗费了多少 Token；
- **提示词与智能体资产无沉淀**：Prompt 与业务 Agent 散落在个人代码或零碎脚本中，缺乏不可变版本管理、发布审核与集中授权。

Omniflux 秉持 **"All intelligence, one current"（万川归流，众智归一）** 的理念，将分散在多个供应商和私有部署环境中的模型能力，收敛到统一的逻辑控制平面中，为企业提供工业级的高可用、强治理与多租户 AI 基础设施。

## 总体系统架构

Omniflux 采用 **管理面（Control Plane）** 与 **数据面（Data Plane）** 严格解耦的双平面架构：

![Omniflux 架构图](/assets/architecture.zh-CN.png)

### 1. 数据面 (Data Plane)
- **高性能标准网关**：对外暴露完全兼容 OpenAI 标准协议的 HTTP 接口（`/v1/chat/completions`、`/v1/embeddings`、`/v1/models` 等）。业务系统仅需修改 `base_url` 与 `api_key`，即可零成本平滑接入。
- **治理化调用链路**：每个请求进入数据面后，按序经历 **身份认证 → 组织/项目授权核验 → 预算与限流检查 → 智能动态路由 → 上游 Provider 转发与 Fallback 重试 → 计量入库与审计留痕**。
- **高吞吐流式处理**：原生支持 SSE（Server-Sent Events）流式响应，内置第一 Token 延迟超时保护（`first_token_timeout_ms`）。

### 2. 管理面 (Control Plane)
- **现代化中后台**：基于 Vue 3、TypeScript 与 Naive UI 构建，提供多租户、模型服务编排、路由策略配置、用量监控、审计查询与资产治理可视化界面。
- **标准化管理 API**：提供完善的 RESTful 管理接口（`/api/v1/*`），支持企业 CI/CD 流程或内部审批系统进行自动化集成。

### 3. 数据存储与基础设施
- **PostgreSQL 17**：持久化存储多租户元数据、账号凭证（AES-256-GCM 加密）、模型服务配置、不可变版本资产、计量明细与审计日志。
- **Redis 8**：提供高性能分布式令牌桶限流与固定窗口频控状态。

## 核心特性矩阵

| 核心领域 | 功能特性 | 业务价值 |
| :--- | :--- | :--- |
| **模型接入与抽象** | 逻辑模型服务 (Logical Model Service) | 业务侧调用逻辑服务名，底层自由映射多模型，屏蔽供应商细节与变动。 |
| **智能动态路由** | 硬约束过滤 + 4D 动态评分 (成本/质量/延迟/可用性) | 自动选择性价比最高且健康的 Provider，支持优先级分组与加权负载均衡。 |
| **容灾与高可用** | 自动故障降级 (Fallback Chain) + 实时健康画像 | 请求失败或超时自动重试下一候选；基于滑动窗口实时计算成功率与降权。 |
| **多租户与权限** | 组织 → 部门 → 项目 → 应用 → API Key 五层治理 | 强隔离租户空间，支持粒度到 Key 的调用权限与独立限流。 |
| **成本与预算控制** | 细粒度计量归因 + 多币种结算 + 实时预算熔断 | 按团队、应用、Key 与模型精准归因 Token 和费用；支持后付预算阻断。 |
| **企业资产治理** | PromptTemplate 提示词资产 + Agent 多轮会话运行时 | 提示词不可变版本管理、变量校验与发布；支持会话保持与状态隔离。 |
| **全链路可观测** | 决策留痕 (PolicyDecision) + Prometheus 指标 + 审计日志 | 每一笔调用的路由决策因由完整留痕，便于性能调优与合规审查。 |
