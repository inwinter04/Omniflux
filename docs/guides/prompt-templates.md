# 提示词模板 (PromptTemplate)

在许多企业的 AI 应用落地过程中，Prompt 常常硬编码在前端页面或 Python 胶水脚本中。一旦需要修改提示词、切换模板或回滚版本，往往牵一发动全身。

Omniflux 将提示词提升为**第一类企业受治理资产**，提供类似代码仓库的版本化、安全变量渲染与权限管控能力。

## 核心设计理念

1. **不可变版本控制 (Immutable Versions)**：每次在管理台对提示词模板的编辑与修改，都会生成一个自增的新版本。已发布的版本内容完全锁定不可篡改，确保线上推理语义的可复现性与历史可溯。
2. **安全变量与严格类型声明**：模板中可声明动态参数（如用户问题、上下文、业务标识），支持严格类型约束与必填验证。
3. **支持一键回滚**：当新发布的提示词版本在线上产生负面效果时，可在管理台一键切换发布指针回退至上一个稳定版本。
4. **多模型独立调试**：在管理控制台内置了调试看板，支持在发布前使用真实模型进行不同参数的对比实验。

## 模板语法与安全规则

Omniflux 采用 **Go Template 的安全白名单子集**：
- 变量引用语法：<code v-text="'{{ .variable_name }}'"></code>
- **只允许读取已声明变量**，禁止执行任意系统函数或反射调用，彻底杜绝模板注入安全风险。

### 变量声明规范
在管理台创建模板时，可为每个变量配置：
- **类型 (Type)**：`string`、`number`、`integer`、`boolean`
- **是否必填 (Required)**：未传入必填参数时直接报错
- **默认值 (Default)**：调用方未传值时的替补值
- **中文描述 (Description)**：便于业务协同理解

## 数据面调用与渲染

PromptTemplate 提供了专门的数据面渲染接口。**渲染端点只负责文本装配与安全校验，不会自动发起上游模型推理**，保证职责分离。

### 1. 查询项目可用的已发布模板
```bash
curl -sS http://127.0.0.1:8080/v1/prompt-templates \
  -H "Authorization: Bearer $OMNIFLUX_API_KEY"
```

### 2. 渲染模板内容
```bash
curl -sS http://127.0.0.1:8080/v1/prompt-templates/customer-service/render \
  -H "Authorization: Bearer $OMNIFLUX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "variables": {
      "customer_name": "张三",
      "issue_type": "退款申请"
    }
  }'
```

成功返回组装完成后的纯文本内容：
```json
{
  "name": "customer-service",
  "version": 3,
  "rendered_text": "你是一名专业的售后客服。用户 张三 提出了一个类型为 退款申请 的问题，请礼貌地协助处理..."
}
```

## 安全与隐私审计原则

- 模板的每次成功渲染与非法调用拦截都会被记录入审计日志；
- **隐私保护原则**：为了防止用户敏感数据泄漏，审计日志中仅记录模板标识、版本号、请求来源与耗时，**绝不记录业务传入的具体变量值与最终渲染出的文本正文**。
